⚡ 1. Single-Pass First-Run Boot (Zero Restart Required)

Unlike traditional Minecraft server loaders that require an initial run to generate configuration files followed by a mandatory manual restart, Vessel completes all 16 boot stages in a single continuous execution pass: 

# 1. Standard Production Launch (Resolves latest Minecraft release, provisions Geyser + Spark, loads all mods & plugins):
java -jar server.jar --nogui

# 2. Maximum Microscopic Performance Bundle (Enables C2ME chunking, Krypton netty, Lithium AI, FerriteCore RAM cache & Alternate Current):
java -jar server.jar --vessel-ultra-optimize --nogui

# 3. Deep Diagnostic Trace Mode (Traces Bytecode Remapping, Fast-Path Routing, Event Buses & Registry Injections):
java -jar server.jar --vessel-deep-debug --nogui

🛡️ 3. Forward & Backward Version Guards

Automatic Backward Compatibility: When the server runs on a modern version (e.g. 1.21.4), Vessel automatically upgrades legacy mod/plugin bytecode in memory (converting new ResourceLocation(...) to modern ResourceLocation.fromNamespaceAndPath(...), migrating Bukkit InventoryView calls to interface invokevirtual, and migrating DataPack paths).
Forward Version Guard: If an operator attempts to load a mod requiring a newer Minecraft release than the running server (e.g., loading a 1.21.4 mod on a 1.20.1 server), Vessel rejects that mod cleanly with actionable instructions instead of crashing the server JVM.

🛠️ Developing Mods for Vessel: Native vs Mixed-Vessel

Vessel introduces a clear, high-performance classification for mods. Mod developers can choose to target Vessel natively to unlock maximum performance or create hybrid mods:

1. [Vessel] Pure Native Mods

  • Package: Must reside in dev.vessel.mod.*
  • Purity: 0% calls to Fabric, Forge, or Bukkit internals.
  • Superpower: Zero-Remap Fast-Path. The server completely bypasses the bytecode remapper, injecting opcodes into Minecraft in < 1 ms!

2. [Mixed-Vessel] Hybrid Mods

  • Structure: Declares metadata for Fabric/Forge but also invokes Vessel Canonical APIs.
  • Engine: Dual-Dialect Semantic Splice. Vessel isolates external calls for standard remapping while fast-pathing Vessel-native calls.
  • Allows seamless gradual migration to Vessel Native APIs.
