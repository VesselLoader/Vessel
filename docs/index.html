1. Quick Start — Single-Pass First-Run Boot (Zero Restart Required)

Unlike traditional Minecraft server loaders that require an initial run to generate configuration files followed by a mandatory server restart, VESSEL completes all 16 boot stages in a single execution pass even on a brand-new directory: 

# 1. Standard Launch (Automatically resolves latest Minecraft release, provisions Geyser + Spark, loads all mods & plugins):
java -jar server.jar --nogui

# 2. Maximum Optimization Suite (Enables SIMD Physics, Zero-Copy Netty, AI LOD, Zstd RAM Cache, Lockless Strands & LazyDFU):
java -jar server.jar --vessel-ultra-optimize --nogui

# 3. Deep Diagnostic Debug Mode (Traces Bytecode Rewriting, ClassLoader Routing, Event Bus Dispatch & Registry Audit):
java -jar server.jar --vessel-deep-debug --nogui

3. Multi-Era Backward Compatibility & Strict Forward-Version Mod Guard

Automatic Backward Compatibility (modMcVersion <= serverMcVersion): When the server runs the latest Minecraft release (or any version equal to or higher than a mod/plugin's target version), LiveJarBytecodeTransformingClassLoader automatically upgrades legacy bytecode in memory (e.g., rewriting new ResourceLocation(...) constructors to ResourceLocation.fromNamespaceAndPath(...), rewriting Entity.level field accesses to Entity.level() method calls, promoting legacy Bukkit INVOKEVIRTUAL InventoryView calls to INVOKEINTERFACE for 1.21+, and migrating DataPack paths loot_tables/ → loot_table/).
Immediate Rejection When Server Is Older Than Mod (modMcVersion > serverMcVersion): If the server is running a lower Minecraft version than the minimum version required by a mod or plugin (for example, running a 1.20.1 server while loading a mod that requires 1.21.4), ForwardVersionModRejectionGuard immediately refuses to load that mod/plugin and outputs an actionable diagnostic message:
"Please install a lower build of the mod/plugin that supports the current server version, or upgrade the server to a higher Minecraft release (--vessel-version=<ver> or default latest.release)."

4. Hourly Zero-Lag GitHub Auto-Updater (Staged Patching & 100% User Data Protection)

  • Automatic Hourly Scan (3600s): HourlyGitHubAutoUpdateDaemon runs on an isolated low-priority daemon thread completely decoupled from the 20 TPS Main Tick Thread (0.00 ms tick lag).
  • Deterministic Version Code (VesselBuildVersionCode): Formatted as VESSEL-<semver>-rev<build>+mc<mcVer>-geyser<geyserVer>-spark<sparkVer>. VESSEL parses this token to determine whether the running server is older (<), identical (== latest), or newer (>) than the GitHub release.
  • Live Update Staging & Apply on Restart: When a newer release is published on GitHub, VESSEL downloads the update into cache/updates/staged/ and immediately refreshes the latest Geyser, Spark, and Minecraft latest.release descriptors without interrupting the running server. Staged kernel patches are automatically promoted at Step 0 of the next server restart.
  • 100% User Data Preservation (UserDataPreservationSnapshotGuard): All user directories and configuration files including mods/, plugins/, config/, vessel.yml, server.properties, eula.txt, and world/ are guarded via SHA-256 integrity snapshots and are never deleted or overwritten during auto-updates.
